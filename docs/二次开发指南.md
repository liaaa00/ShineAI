# 二次开发指南

## 文件结构

| 目录或文件 | 用途 |
|---|---|
| `src/main/bootstrap.cjs` | 可读的启动入口；先配置隔离和访问边界，再加载发布代码 |
| `src/main/runtime/config.cjs` | 数据目录、开发版名称和端口配置 |
| `src/main/extensions/` | 新功能的主进程模块；优先在这里开发 |
| `src/main/security/` | IPC 来源检查、官方云服务拦截，以及保留的本地访问检查工具 |
| `src/main/extensions/local-identity.cjs` | 固定本地身份，不读取或刷新官方账号 |
| `src/main/extensions/removed-cloud-services.cjs` | 无网络的旧调用兼容接口，不启动云服务 |
| `src/main/extensions/claude-effort.cjs` | Claude 中转模型 effort 传递与下一轮更新 |
| `src/main/extensions/codex-endpoint.cjs` | Codex 中转根地址补全，与测试及会话配置共用 |
| `src/main/extensions/async-process.cjs` | 非阻塞的环境与工具检测子进程 |
| `src/main/extensions/provider-proxy.cjs` | 直接读取代理环境及应用配置，不启动 PowerShell 或记录代理凭证 |
| `src/main/extensions/port-discovery.cjs` | 异步查询运行中的监听端口及 Windows 保留端口 |
| `src/main/extensions/screenshot-shortcuts.cjs` | 开发版截图快捷键、冲突回退和实际按键保存 |
| `scripts/patch-local-responsiveness.mjs` | 使用语法树接入异步环境检测、启动环境读取及快捷键修复 |
| `scripts/patch-claude-effort.mjs` | 使用语法树接入 Claude effort 修复，保存上游重建变换 |
| `scripts/remove-official-cloud.mjs` | 使用语法树移除官方云发布类及对应界面 |
| `src/main/index.js` | 解码字符串后的官方主进程发布代码 |
| `src/preload/index.js` | 前端可以调用的受控接口 |
| `src/preload/development.d.ts` | 开发版接口类型；新接口同步添加类型 |
| `src/renderer/` | 官方界面发布代码及资源 |
| `out/` | 自动生成的运行输出 |
| `archive/official-1.0.6/` | 未修改的应用代码、逐文件校验记录 |
| `archive/official-1.0.6.asar`及对应`.unpacked` | 完整官方客户端包和原生文件，供离线恢复依赖 |
| `.runtime/electron/` | 独立 Electron 44.5.1 运行环境 |
| `.runtime/node_modules/` | 测试、解析与格式化工具 |
| `scripts/packaging/` | 独立打包工具的版本及完整锁文件 |
| `scripts/package-windows.mjs` | Windows 安装构建；显式清单排除个人数据，保留原生 ABI |
| `scripts/installer-smoke.mjs` | 实际安装、启动、本地功能和卸载验收 |
| `resources/` | 工程自己的内置技能、MCP、工具、语音和其他配套文件 |
| `.data/` | 正常开发版数据，不进入版本控制 |
| `.test-data/` | 自动测试的独立数据，不使用官方数据 |
| `artifacts/` | 自动生成的校验报告和截图 |

## 新增一个功能

先参考 `src/main/extensions/runtime-info.cjs`。为新功能建立单独模块，在 `bootstrap.cjs` 中注册主进程处理函数，然后在 preload 中暴露具体方法。前端通过这个方法调用，接口参数应验证类型、范围和用户选择的目标。

现有示例：

```typescript
const runtime = await window.development.getRuntimeInfo();
console.log(runtime.version, runtime.edition);
```

权限检查由主进程执行，前端的按钮状态只是界面提示。远程网页和任意 iframe 不能直接调用本地应用 IPC。终端、文件写入和网络操作应使用明确的业务接口，并限制到实际需要的路径和用途。

## 修改现有发布功能

优先从 preload 中找到对应的方法和通道，再在主进程代码中搜索该通道名称。一次只整理一个小功能，不同时重写会话、模型调用、数据库和窗口管理。变更行为必须有真实触发场景，测试覆盖最终结果。

`scripts/decode-main.mjs` 静态解码字符串，不执行官方主程序；它只在隔离环境中执行字符串数组和解码函数。`scripts/apply-dev-transforms.mjs` 保存开发版隔离、账号和兼容修改。重复应用变换时会检查关键结构，未知上游布局会报错。

`npm run decode:upstream` 会从原始快照重新生成主进程发布代码，因此只用于重新提取或重做转换；普通开发使用 `build`。运行此命令前应提交或备份你对 `src/main/index.js` 的修改。原始快照只作对照，不直接编辑。

## 更新官方版本

1. 保存并提交当前开发修改。
2. 在新的版本目录保存安装包、原生文件、逐文件哈希及真实版本信息。
3. 保留当前版本运行环境，单独验证新版 Electron、Node 和原生 ABI。
4. 先对照新版变更，再迁入可读扩展和最小必要变换。
5. 通过构建、真实窗口、项目、终端、AI 对话及恢复验证后，再切换日常使用入口。

当前版本已移除官方登录、会员、内置模型、组织协作、云会议、中继、发布、遥测和更新。更新上游时应重新应用云服务移除变换，不能直接覆盖本地版。原始官方实现仅供 archive 对照。自备模型服务商的认证与网络请求仍保留，账号和额度由实际服务商验证。

公开技能与 MCP 市场需保留，包括官方公共目录、skills.sh、用户配置的 registry 地址；不要按“官方”标签或需要联网一概屏蔽。`npm run smoke:market` 使用独立数据验证市场展示、按钮安装、正文下载与重启保存，不执行安装的技能，也不调用收费模型。下载测试使用本地 HTTP 源隔离外网故障，默认目录展示仍走现有公开目录及内置回退逻辑。

`runtime-info` 的 `officialCloud` 为 `removed`，运行端口返回 `null`。配置文件中的登录与会议端口，以及 `getServiceAccess` 的旧访问元数据仅作兼容预留，不代表当前存在服务监听。不要把保留的 preload 方法当作云功能仍可用的依据；旧调用会收到明确的已移除结果。

## 检查和备份

`npm run check` 验证关键边界和真实窗口，`verify:baseline` 证明原始快照未改变，`verify:reproducible` 比较两次生成输出。新增接口优先增加覆盖实际风险和结果的测试。

`npm run e2e:local` 在独立临时工作区实际测试项目、文件、Git、终端及重启保存，不读取服务商密钥或发起模型请求，结果单独写入 `artifacts/local-e2e-report.json`。

`npm run smoke:local` 验证真实窗口中的截图按键注册、占用回退、保存与重启恢复，并在完整环境检测期间测量其他 IPC 的响应时间。该检查也纳入 `npm run check`。开发版默认截图按键为 `Ctrl+Alt+Shift+S` 和 `Ctrl+Alt+Shift+W`，冲突后选择可用备选并保存实际生效值；主动禁用的按键保持禁用。

`npm run e2e` 还测试模型回复、会话保存和继续会话。它使用本机已配置的 Codex 服务商，会消耗少量额度；不纳入普通 `check`，避免每次改代码都调用模型。具体证据与未测范围见 `功能验证.md`。

`provider-defaults.cjs` 只为首次本地数据配置默认服务商，之后保留用户选择。`codex-routing.cjs` 保留用户自定义的 Codex 服务地址选择，同时保留会话专属 MCP 配置；它只修改应用生成的会话配置，不写全局 Codex 配置。

运行 `powershell -ExecutionPolicy Bypass -File scripts/backup.ps1` 创建完整开发工程备份。默认不含 `.data` 和 `.test-data`；需要包含正常用户数据时，加 `-IncludeUserData`，并先关闭开发版，使数据库处于一致状态。备份包含恢复运行依赖需要的安装包和运行环境。
