本轮按用户要求只分析，未改应用代码、配置或安装文件，未向真实会话发测试消息。

上次新增的是本地消息显示及失败恢复，未优化后台的发送准备。其“正在发送”表示
发送回调尚未完成、正式消息尚未匹配回传；不能据此判断模型已经或尚未开始推理。
独立模拟服务测试验证了显示行为，不能证明实际项目目录的快照没有耗时。

只读 Git status 校验在约 384ms 返回成功，这不能验证实际 add/commit 成功。

上次改动没有增加人为等待计时器或发送队列，但只解决显示空档，不解决发送延迟。
现有单一状态把本地准备与适配器确认混在一起，故用户无法从界面分辨阶段。
后续若授权修复，应先保留具体 Git 错误及阶段耗时，在用户实际项目目录复现，
修复快照故障并避免失败快照反复拖慢发送。快照必须在模型修改文件前完成或明确失败，
不能简单放到模型开始后的后台执行，否则会破坏文件回滚的基准。
