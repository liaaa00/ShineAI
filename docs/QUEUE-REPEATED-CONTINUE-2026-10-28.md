# “继续”长期显示排队的问题

截图所对应的历史会话在 2026-10-28 20:38:58 收到执行引擎的成功轮次结束事件，随后用户手动终止/恢复会话，在 20:55 再收到新回复。程序主进程从 10 月 26 日持续运行，安装目录中的新进度代码尚未由该主进程加载。

发现两个实际缺陷：

1. 运行消息过滤器将旧 SDK `submitted` 记录也当成待处理重复消息，未核对本地队列是否仍持有它。用户发送同样的“继续”会直接收到 scheduled 响应，原发送方法没有被调用。现在只对确实在本地队列里的输入或正在执行的发送操作去重；离开本地队列的历史 SDK 提交保留审计记录，不能拦住新的同文消息。
2. 发送预览使用 `Date.parse` 匹配回显，未处理数字时间戳；也未根据稳定输入 ID、真实投递回执和 SDK 队列持有状态更新。现在兼容数字与 ISO 时间戳，优先依据明确输入 ID，合并同一输入 ID 的重复预览，并根据真实投递证据删除过期提示。未知 SDK 送达不能伪装为模型已收到，离开队列时显示“已提交，等待会话显示”。

不自动重发历史送达不确定的请求，不改用户数据库，不取消运行中的任务。

验证：224 项单元测试通过；新增隔离 Electron 检查覆盖实际输入框连续发送、实际 HTTP 请求包含补充输入、结束后同文新消息真正再次发送以及排队提示收尾。数值时间戳额外通过隔离渲染数据验证。测试不使用付费模型、不修改实际会话。

`npm run check` 已执行：单元、构建、一致性验证、桌面启动、云隔离及 Codex 检查通过；本地环境检测 IPC 性能检查未通过（2495 ms，阈值 1500 ms），属于先前已存在的失败，没有放宽判断标准。实际报告见 `artifacts/queue-check.log`、`artifacts/queue-echo/report.json` 和安装版子目录的报告。
