# 官方 1.0.8 记忆核心更新

用户确认在保留已有记忆的前提下，跟随官方本次记忆更新。此轮覆盖记忆核心，不代表把整个官方应用或工作分组流程替换为 1.0.8。

## 更新后的行为

- 记忆评估使用官方新版的 `general` 分类。模型判断为所有会话都适用的通用规则、通过原有准入检查且已经生效时，user/feedback 记忆可以自动获得 `pinned` 标签。project 记忆不会因 `general` 自动置顶，待审内容也不会因此直接置顶。`general` 只接受布尔值 `true`，字符串 `"true"` 不会触发。
- 会话开场的记忆预算为 3500 字、最多 18 条，置顶最多 6 条，普通最多 12 条。按官方顺序优先置顶，再结合话题重合和衰减分数排序，仍受总字数限制。实际传入的上下文包括用量说明与使用规则，因此不保证每次恰好装满 18 条。
- 置顶可以绕过话题相关性筛选，但不会绕过项目可见性、待审、失效、冻结等过滤。冷层已确认的规则可注入；未确认的冷层内容不因此生效。项目事实继续主要通过 `memory_recall` 检索。
- 保存权限保留官方策略：平衡档的高置信度自动记忆可直接生效；谨慎档初次进入待审。官方既有后台维护仍可能把符合条件的 user/feedback 候选转为有效记忆，这不是“每条都必须人工批准”。界面既有“已确认”标签也不能据此推断用户曾点击批准。
- 用户已有的记忆 ID、内容、项目范围、标签和配置不被本次迁移重置；现有记忆不会为了升级而全部重新评估或批量置顶。

## 数据兼容与备份

不更改记忆文件格式，也不迁入官方账号的记忆目录。继续使用 ShineAI 原有 `.shineai/butler`，测试使用独立资料目录。

首次由新版本读取已有记忆前，把 `memory` 目录原始字节备份到 `butler/backups/before-memory108-*`。快照清单保存文件路径、长度和 SHA-256；成功后写入 `.memory108-upgrade.json` 标记，重启不反复覆盖原快照。备份失败时不标记迁移完成；不会先删旧数据再尝试恢复。

备份只是升级保护，不替代记忆维护：新版本正常运行后，官方原有去重、衰减、整理等功能仍可按已有设置更新内容。

## 保留的 ShineAI 修复与本次边界

- 模型未配置、调用失败、返回格式无效、队列满、仍在评估和写入失败保持各自的反馈，不能冒称内容不值得保存或已保存。
- 保留既有语义准入：涉及“部署”“完成”等词的长期规则，不会只因这些词而被拒绝；临时进度、凭据和内部通知仍受过滤。官方注入器也复用这一准入规则。
- 基于官方完整评估提示词增加 `general`，保留“不调用工具”的一次性评估要求。修正其“无用户审核”的失实表述，由程序根据权限决定待审或生效，并补充既有语义和保存结果说明。
- 现有后台自动确认路径与权限档位跟随官方行为，没有额外强制改成逐条人工审批。
- 本次没有迁入工作分组的简报、技能推荐、决策提案审批等新流程；现有分组功能保持原集成。官方账号、遥测和托管云服务保持移除。

## 工程与验证

官方原包与解码输入都固定 SHA-256。`scripts/import-memory108.mjs` 抽取官方注入器及提示词，生成可读模块 `src/main/upstream108/memory.cjs` 和来源清单 `memory-manifest.json`。`scripts/patch-memory108.mjs` 只接入注入器、状态预算、两处保存标签及备份入口；不会覆盖整包主程序。日常构建不需要官方恢复目录或解码缓存。

`test/memory108.test.mjs` 验证预算、置顶、可见性、冷层规则、排序、实际自动保存方法、严格布尔分类、备份与重放幂等性。原有记忆和会话恢复测试继续保留。`npm run smoke:memory108` 使用完整 Electron、独立资料目录和本地模型测试服务，覆盖旧格式记忆加载、实际 `memory_save`、错误反馈、重启及后续模型请求。

完整应用检查使用 `npm run check`。本机测试不代表真实模型的提取准确率，也不代表 macOS 已实测。
