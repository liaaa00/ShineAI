# 修复自动文件快照拖慢发送

已确认的回归来源：`patch-execution-experience.mjs` 为了保证任务前文件基准，在调用适配器
之前等待 `captureSnapshot`。原快照每个 Git 命令可等待 60 秒，未给完整发送准备设置预算。
这会把原来后台快照的慢操作变成用户发送前的等待；新增消息预览只修了显示空档。

本次通过 `snapshot-budget.cjs` 在已有保护入口限制自动快照：

- 完整快照共享 3000ms 预算，每个实际子进程只能使用剩余时间；超时等待子进程结束后再放行。
  系统调度与终止收尾可能超过该预算，不能将其表述为严格三秒内完成所有发送准备。
- 同会话失败后冷却 60 秒，期间跳过自动快照，不反复让每条消息承担失败成本。
- 只对自动捕获使用独立临时 Git index。终止后清理该次 index/lock，不删除别人持有的锁。
  原项目 Git 仓库、用户文件和普通手动撤销操作的超时设置不变。
- 失败写入不可用基准记录，解析时不将其当作 Git 提交，防止本轮错误继承旧快照。
  记录存入原快照表，重启后仍有效。缺快照继续允许对话回滚，禁止伪造文件恢复成功。
- 记录 Git 阶段、失败类别、耗时和截断的本地错误；过滤 URL 和常见密钥格式。

验证范围：

- 自动快照预算测试使用真实子进程，验证超时终止、之后不再写入、总预算、失败冷却、
  临时 index 清理和普通撤销执行不受自动预算影响。
- 原有真实 Git 文件恢复测试继续验证任务前未提交编辑、预览冲突、重做冲突和忙碌拦截。
  该内容测试在并行套件下显式给冷启动 Git 留 15 秒；三秒预算另由独立取消测试与实际发送验证。
- 用实际 SQLite 与原 RollbackService 验证：失败记录持久化、重启不复用旧成功基准、
  缺快照预览返回仅对话。报告：`artifacts/snapshot-budget/db-report.json`。
- 隔离 Electron 对 `D:/AI/SpeceAppDate/中转站` 发送固定本地模型请求，使用独立 shadow
  仓库，不修改用户项目文件，也不在用户会话中测试。首次请求到达本地测试服务耗时 4933ms，
  自动快照在约 3345ms 终止（冷启动阶段为 git init），后续捕获在冷却期以 0ms 跳过。
  保留完整消息预览、长历史滚动、正式回传去重、发送失败恢复和明确重试检查，全部通过。
  报告：`artifacts/snapshot-latency-source/smoke-report.json`。

实际付费模型的首包和推理时间不属于本地请求耗时结论。当前修改处理了自动快照的阻塞路径，
没有保证任何模型即时响应。自动快照未完成的轮次没有文件撤销能力，界面原预览会如实显示。
