# Codex 中转连接测试修复

日期：2026-10-13。适用范围：开发版 `codex-appserver` 适配器和自备 OpenAI 兼容中转。

## 现象与原因

设置页在 API 基础地址只填写站点根地址时，原测试逻辑直接拼出 `/chat/completions`，收到某些中转站的 405 后，仅在错误正文包含特定短语时才改试 `/responses`。Codex 实际使用 Responses API；测试协议与会话协议不一致，而且缺少 `/v1` 路径，因此 405 不能可靠说明密钥无效。

现在，对仅含站点域名的 Codex 基础地址自动补 `/v1`；已指定路径的地址保持原意，避免改变中转站自定义前缀。Codex 设置测试直接请求 `POST <基础地址>/responses`。会话生成的 Codex 配置和图像代理上游也使用相同的根地址补全规则。普通 `openai-api` 适配器仍按原有 Chat Completions 优先策略测试。

后续发现，原测试还会等待模型生成完整 JSON；它过早停止请求计时，界面则在 12 秒后显示通用超时提示。Codex 连接测试现改用流式请求，在收到实际文本、思考或工具参数输出，或有效完成响应后结束测试，无须等待完整回答；请求与正文合计最多等待 40 秒，界面的 Codex 测试提示在 45 秒后才超时。其他适配器仍沿用原等待设置。

本地复查还发现，部分中转可能先返回 HTTP 200，再用 SSE 的 `error` 或 `response.failed` 报错。测试现在解析响应事件，不能仅凭 HTTP 200 或 `response.created` 显示成功；JSON 错误、HTML 页面、空响应、过大响应和正文停滞都会明确失败。接入保存在可读扩展及重建变换中，重复转换不会丢失。

如果修复后仍得到 405，应确认中转站实际提供的 Codex/Responses API 基础地址以及是否接受该路径的 POST 请求。连接测试成功只证明测试请求被接受，不保证所有模型、工具和长会话均可用。不要用已公开的密钥继续测试；应先撤销并换新。

## 验证

- `node --test test/codex-endpoint.test.cjs test/codex-routing.test.cjs`：覆盖根地址、显式路径、Responses 请求、405、HTTP 200 后的流式错误、JSON 回退、分片事件、正文超时、响应大小限制和原有自定义路由。
- `npm run smoke:codex`：真实开发版 Electron 窗口调用 preload 测试接口，并点击设置页 Codex“测试”按钮，两次请求均为 `POST /v1/responses`；本地模拟中转不使用真实密钥或付费模型。用 `CODEX_PROBE_SLOW_MS=15000` 再测时，界面在超过旧版 12 秒限制后仍显示连接成功。
- `npm run check`：全量单元测试、构建、输出校验、实际窗口和云服务边界检查通过。
