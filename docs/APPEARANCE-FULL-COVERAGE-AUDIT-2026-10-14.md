# 全量外观盘点与验收规则

静态分析日期：2026-10-14。以下分析保留实施前的现场记录，当时尚未修改程序。用户随后授权实施；2026-10-15 的实现与验收记录见本文末尾及 APPEARANCE.md。

## 用户目标

同一张背景贯穿应用自身所有界面。页面、工作台卡片、验收抽屉、弹窗、菜单、输入框、搜索框、代码区域均应受外观配置控制。不能以“保留阅读底色”为由让其中某类继续完全不透明。文字、图标、边框与状态颜色保持可辨认，透明度只作用于底色。

全量效果不等于强制每个区域无色。正确目标是：所有界面底色都使用同一套可调材质，不再出现不受配置控制的实心白块；强调按钮的填充也应跟随透明度，状态含义通过色相、文字、边框与轻微着色保留。图片、视频、文档内容及外部网页的原始颜色与界面底色是不同对象；系统原生文件选择框也需要按实际技术边界单独记录。

## 背景来源清单

静态明细见 `artifacts/appearance-audit/background-inventory.json`。扫描对象为两个主要业务 JavaScript bundle，以及画布样式、主样式和新增外观样式。扫描没有执行被分析的模块。

| 来源 | 实际存在的写法 | 统一处理要求 |
| --- | --- | --- |
| 原主题工具类 | `bg-bg-primary`、`bg-bg-secondary`、带 /40、/95 等比例的变体 | 中性底色统一引用外观材质；覆盖常态、hover、active、selected、disabled，不依赖组件名字名单 |
| 自定义组件样式 | `.cn-node`、`.cn-peek`、`--cn-bg`、`--cn-panel` | 将组件派生背景接入材质；保留状态颜色、边框和文字配色 |
| V2 工作流主题 | `--v2-bg-canvas`、`--v2-bg-panel`、`--v2-bg-input` 等 | 同步所有 V2 中性底色，消除目前 94% 不透明的独立面板材质 |
| 内联背景 | `style.background`、`style.backgroundColor`、引用变量或显式颜色 | 引用 V2 变量的自动随变量变化；直接设置中性色的声明需要分类适配，强调色和进度条不应被当作中性底色清掉 |
| Portal 和浮层 | 主 bundle 51 处 createPortal 调用，工作台 bundle 3 处 | 材质变量必须在 html 等可继承范围生效，不能仅限定在 #root 后代；覆盖菜单、提示、预览及弹窗 |
| 自行绘制的组件与独立窗口 | xterm、Monaco、XYFlow、图表以及原生窗口按钮 | 分别确认绘制背景和窗口入口；CSS 父层透明不代表内部画布透明，独立窗口必须实际打开验收 |

静态扫描记录主 bundle 2995 条候选背景引用，工作台 bundle 109 条。它们包含重复使用、悬停效果、透明背景、强调色和库代码，不是 3104 个已确认缺陷，也不能用已标记数量计算外观覆盖率。另有强调色、显式白/黑/灰色及遮罩的补充工具类引用清单，可能与基础清单重叠；需要按界面底色与数据/状态含义分类。三个 CSS 文件分别记录 84、569、19 条候选背景声明。动态 class 的间接常量、运行时生成样式和画布最终像素仍需运行验收。

## 现有测试为何没有发现问题

1. 全局区域测试进入工作台后检查了画布，没有打开会话卡片对应的 SessionDrawer，因此没有检查最新截图的验收抽屉。
2. 专家页测试明确采样卡片之间的空白区域，证明了页面底层变化，没有证明卡片跟随透明度。
3. 工作台测试要求输入面板继续有局部背景，但没有要求这层底色跟随透明度，更没有排除其接近不透明。
4. 主页面一块采样区域的像素有变化，不代表页面内所有控件和弹出状态都正确。
5. 工程测试、语法检查和构建完整性证明程序可构建和相关逻辑有效，不证明全量视觉目标已达成。

过去的测试结果在其实际范围内有效，但“全局检查通过”这一描述超出了实际证据。新的验收必须同时包含页面、具体组件与触发后的状态。

## 建议统一规则

- 保留一份窗口级背景媒体；所有界面材质透出同一份媒体，不能在每个卡片里复制、重新裁切或播放一次壁纸。
- 基础主题颜色用于文字、强调色和颜色计算；新增材质变量专用于背景，避免把需要 HEX 的颜色接口直接改成 CSS 透明表达式。
- 结构外壳负责布局；卡片、输入框、菜单和弹窗负责轻微层次，全部跟随统一透明度。需要区别层级时使用边框、阴影和适度模糊，不能用不可调的实心白底。
- 强调按钮、警告/成功提示的面板底色同样可调；文字、边框、进度条和图表数据颜色保留原有含义，不能把界面填充与业务数据图形混在一起清除。
- 原工具类、自定义组件变量、V2 背景变量与必要的内联声明统一映射到材质，逐步替代目前的组件名字名单与特例匹配。
- 默认、悬停、选中、禁用、展开菜单、切换主题和新挂载组件都必须沿用材质规则；不能只修改首次渲染。
- 避免对整个元素设置 opacity，因为这会连文字一起变淡。避免多层父子面板反复叠加高不透明度，导致局部再次变成白块。
- 透明度最高时不应留下由应用绘制的实心中性面板；透明度为零时恢复原主题的中性底色；关闭背景时取消材质覆盖并恢复原行为。
- 动态壁纸只由窗口级媒体播放，窗口隐藏/减少动态效果继续遵守现有暂停策略。模糊不应无差别铺到每个控件，避免性能下降。

## 逐项验收清单

全部使用隔离数据和生成媒体，不修改用户日常会话，不发送真实模型请求。

| 操作/界面 | 必须检查的具体内容 |
| --- | --- |
| 工作台有卡片状态 | 待处理/在跑/收藏分组、会话节点、提示条、工具栏、输入外壳与内层输入框 |
| 打开会话卡片 | 验收面板的根背景、标题、状态、按钮、验收内容、内层说明卡片与回复框；复现最新截图布局 |
| 验收面板切换标签 | 验收、对话、文件改动、面板内终端及更多操作菜单 |
| 悬停与右键 | 偷看卡、右键菜单、下拉列表、悬停高亮与选中状态 |
| 项目会话 | 实际正文、用户/助手消息、代码块、表格、顶部标签、底部输入框、错误或等待提示 |
| 文件与编辑器 | 文件树、搜索框、文件标签、代码/Markdown 编辑器、差异视图及其工具栏 |
| 终端 | 工作台终端、面板内终端、标签、选择文字、ANSI 配色、真实 echo 输出 |
| 设置 | 设置导航、外观预览和配置卡片、服务商配置、添加/编辑弹窗、选择模型下拉菜单 |
| 公共市场 | Skill/MCP 列表、搜索、详情、安装配置及失败提示，不删除或屏蔽市场功能 |
| 专家与团队 | 专家卡片、详情、团队模板、创建/编辑弹窗和筛选按钮 |
| 工作流 | 列表、编辑画布、节点卡片、节点检查器、任务抽屉和画布菜单 |
| 其他工作区 | 项目看板、知识库、定时任务、统计、设计页面及各自的详情/编辑状态 |
| 独立应用窗口 | 实际打开应用支持的独立窗口，确认媒体加载、主题、设置同步与标题栏；未打开的标为未验收 |
| 明暗与状态 | 至少分别验证浅色/深色，透明度 0/中间值/100，默认/hover/selected/disabled，背景关闭与开启 |
| 媒体与布局 | 图片、GIF、视频、不同窗口尺寸、分栏与抽屉宽度；不出现每块各自裁切的壁纸或多份动态播放 |
| 功能恢复 | 背景切换、重启保存、恢复默认、清除媒体、鼠标/键盘交互与真实终端输出继续有效 |

验收方法：以像素变化验证实际区域，以可见中性背景清单寻找残余不透明层，以不同类型壁纸检查文字可读性。单个页面只测一个空白矩形不能作为通过条件。普通界面内容、外部网页内容、文件选择等系统窗口需要在报告中明确区分所有权和实际测试范围。

## 实施顺序

1. 先改统一材质规则，让普通背景类、自定义画布变量、V2 变量和浮层都接入同一配置。
2. 以用户最新的工作台 + 会话卡片 + 验收抽屉 + 输入框 + 终端组合为首个验收场景，确认全部中性背景可调。
3. 按上表打开各页面及隐藏状态，对未接入的内联颜色、Canvas 与独立窗口做具体适配。
4. 修订旧测试中保留实心局部底色的假设，执行工程检查与完整视觉/交互验收，记录未覆盖边界。
5. 验收通过后再更新安装目录并重启。不能以新增背景标记数量或主画布通过代替全量验收。

本报告提供范围、已证实原因、实现方向和验收标准；不表示上述实施已经完成。
