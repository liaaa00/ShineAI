# 小光悬浮窗与任务总览修复

## 根因和行为

- 所有窗口共用 `renderer/index.html`，无条件加入的版本说明在 80×80
  小光窗口中换行到 121.5px 高并覆盖头像。现在通过窗口路由标记在首帧
  隐藏悬浮窗的版本说明，主窗口仍保留版本说明。
- 收起和提示状态隐藏整窗壁纸，并保持 body/root 透明；展开总览保留现有
  壁纸与材质。只调整窗口用途，不修改用户的透明度、字体或壁纸配置。
- `waiting_input` 是等待下一条用户消息，不代表需要审批。现在计入
  “空闲/暂停”，行内显示“等待新消息”。只有待处理事件、明确的注意标记
  或审批/提问等状态才计入“待处理”。失败与已结束状态优先于旧事件。
- 原版按状态生成 70%、55% 等数字，并按运行时间增加进度。现在只有
  明确的数值进度字段或已确认的结束状态才显示进度条；失败不再显示 100%。
- 窗口标题改用“小光 · 任务总览”，同时保留自定义角色名。

可读逻辑位于 `src/renderer/assets/dev-butler-overview.mjs`。
`scripts/patch-butler-overview.mjs` 提供可重复的窄补丁，并接入开发转换流程。

## 验证范围

- `npm run check`：140 项单元测试、构建、静态检查、基础应用、云服务
  移除与 Codex 服务商测试通过；本地环境检测的 IPC 延迟为 1564ms，超出
  1500ms 阈值，整套命令因此返回失败。未放宽阈值或隐藏失败。
- 被前一项阻断的编辑器检查单独运行通过。
- `node scripts/butler-overview-smoke.mjs` 在隔离用户目录运行真实 Electron
  悬浮窗，验证无壁纸/有壁纸的收起状态、展开后壁纸、状态计数与筛选、
  待确认与恢复空闲、真实/缺失进度、标签页、打开对应会话、自动收起和
  关闭后重新打开。测试无真实模型请求，不向用户聊天写入消息。
- 窗口尺寸断言兼容 Windows 150% 缩放的 1px 舍入。透明度检查测量实际
  颜色 alpha，兼容浏览器 rgba/oklab/color(srgb) 的不同序列化。

日志与截图：`artifacts/butler-overview-fix/`。

## 安装版结果

安装版隔离测试 `node scripts/butler-overview-smoke.mjs --installed` 的八项
检查全部通过，无 renderer 异常。四个变更文件先备份后更新；检测到任务
结束且无未保存编辑后，在空闲状态重启主应用。验证保留全部六个已保存
会话、三十个技能、原配置目录与外观配置，安装文件与构建清单一致。

真实用户窗口再次操作确认：收起时为 80×80、版本说明隐藏；总览里五个
当前已加载的普通等待会话都归入空闲，显示“等待新消息”，没有虚假进度条。
保存会话总数与运行时加载数不同，不强行恢复未加载的会话。
实拍证据是 `live-collapsed.png` 和 `live-expanded.png`。
