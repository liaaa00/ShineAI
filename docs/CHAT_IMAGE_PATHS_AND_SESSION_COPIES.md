# 聊天图片路径与会话副本

## 原因

回答中的一行同时包含项目目录、提交记录和反引号括住的截图路径。旧的整行正则把它们合成一个文件地址，文件读取接口因此返回 ENOENT。另查截图原文所指文件已不存在，无法从消息中的文字恢复图片。

## 当前行为

- 复用聊天渲染器现有的 Markdown 解析器，分别提取行内代码中的图片路径；完整独立图片路径及“截图：路径”继续支持。
- 项目目录、提交记录、普通链接和代码块不会被拼接成图片地址。正文不被改写；标准 Markdown 图片仍通过原有组件显示。
- 聊天组件读取本地图片时，先由原有文件读取接口校验权限和路径，并沿用现有 10 MiB 图片读取限制。成功读取后，按会话与原始绝对路径保存本地副本。
- 原文件缺失时，只有同一真实会话、同一原始路径、相同规范路径且当前仍获准读取，才能使用副本；不会替换仍存在的文件，不会绕过黑名单或目录链接变化。
- 副本保存在应用数据目录的 chat-images 下，仅本机使用，不上传。它记录该路径最近一次成功读取的图片，不是每条消息的独立版本归档。会话删除时清理对应副本。
- 没有原文件也没有副本时，显示“图片文件不存在，且没有可用的会话副本”。保存副本失败不会阻止当前原图显示。

首次加载前已经丢失的图片无法补存。只保留一个路径的文字记录，不能恢复图像内容。本次修复不修改用户历史消息或生成替代截图。

## 实现与验证

- renderer/assets/dev-chat-images.mjs：路径提取与缺失提示。
- main/extensions/chat-image-cache.cjs：已有读取接口的副本封装与会话删除清理。
- scripts/patch-chat-images.mjs：可重复应用到重建源码的窄补丁，已纳入恢复流程。
- scripts/update-installed-chat-images.mjs：独立安装目录更新、备份与出错回退。
- npm run check：175 项测试、构建和项目检查链通过。
- node scripts/chat-images-smoke.mjs：隔离数据下实际聊天渲染、文件读取、重启、原图删除后的副本显示、会话删除清理均通过。
- 安装版同一脚本追加 --executable=E:/AI/ShineAI/ShineAI.exe；证据在 artifacts/chat-images/installed。不会关闭用户原窗口或使用用户会话进行测试。

安装目录更新不会重新生成安装包，也不会热替换已经运行的主进程。完全退出并重新启动 ShineAI 后加载修复。
