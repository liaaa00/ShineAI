# 记忆方案与现有功能的兼容性核对

日期：2026-10-21。范围：读取现有主进程、渲染层、运行中输入与后台任务扩展，以及之前的只读复现结果。未修改应用代码、配置、数据库、已有记忆或安装版，未重启程序。本文是静态兼容性审计，不代表完成了新方案的运行验收。

## 结论

可以改进，但不应另建一套记忆系统。现有程序已经具备分类、作用域、同主题合并、版本证据、候选审核、后台评估、过期和向量检索。此前方案中的这些部分应改为复用和补齐；新增机制必须接入现有读写链路。

| 现有功能及源码依据 | 直接照原方案增加的风险 | 兼容做法 |
| --- | --- | --- |
| `saveExplicitMemory`、工具分发和界面使用 `user / feedback / project`，界面已有候选、确认、归档、过期等状态 | 把“规则 / 事实 / 事件 / 会话状态”直接作为新顶层类型，可能被工具降为 user，或无法参与已有筛选 | 保留现有类型；长期核验原则映射 feedback，项目知识映射 project，用兼容 metadata 补用途。历史事件按需保存来源入口，会话状态留在检查点中，不一律写入长期记忆 |
| `upsertMemory`、`resolveSubjectKeyWithSemantic` 已有项目隔离、主题匹配、证据、最多 5 条旧 claim 历史及向量同步 | 再建“同主题更新”系统会重复合并；只按新写入时间覆盖，可能让旧摘要改写较新的已确认事实 | 复用现有更新和 change 事件；补充来源消息、实际观察/核验时间，区分事实与推断。相似度只找候选，冲突、不同实体和未经核验的新说法不能据此直接覆盖 |
| `saveExplicitMemory` 在校验失败后调用 `tryDemoteSameSubjectOnCompletion`；`memory_update` / `memory_forget` 可归档失效知识 | 一刀切删除状态过滤，会改变完成句的分流，可能把“任务已解决”又存成活跃长期记忆；也可能不再让旧问题失效 | 区分长期规则、最后已知状态、历史事件和完结请求；保留显式更新/遗忘入口。校验器不能仅因出现“部署”就拒绝规则，也不能把准入放宽等同于自动保存所有状态句 |
| `runMemoryEvaluation` 按 `Cq("memory", ...)` 进入自动或 proposal；界面候选统一进入“待你拍板” | 新分类器直接落 active 会绕过谨慎模式；显式记住和自动推断的授权语义不同 | 沿用既有候选审核、权限及遗忘规则。显式记住只表达保存意图，不绕过内容脱敏、项目范围和必要校验 |
| `buildMemoryContextWithDetails` 只对相关且符合准入的 user / feedback 做有限热注入（8 条 / 2000 字）；project 明确走 recall。自动召回默认关闭 | 全量注入项目事实会改变现有开关与预算，让旧事实干扰当前会话 | 保留开关、按需检索与预算。加入的来源入口也需相关性筛选；保存成功不等于必然注入，不承诺每次新会话自动知道当前生产环境 |
| 显式与自动评估已有共享并发计数、队列、模型配置与 pending；`evaluateWorthiness` 在缺模型/调用失败时会返回 worthRemembering=false | 新增一次同步模型分类会增加发送等待；只改最外层提示仍可能把模型故障误报为“不值得记” | 在现有评估调用内分类，不在消息发送前增加阻塞。区分未配置、模型失败、真正无有效内容、排队和落库；保持旧结果字段兼容，必要时补机器可读原因与真实持久化状态 |
| `upsertMemory` change 事件、磁盘一致性、向量索引、压缩/整合维护共同管理记忆 | 只给保存入口加字段，可能在编辑、导出导入、后台合并/压缩时丢失，或把普通更新时间误作核验时间 | 采用可向后兼容的 metadata，验证整个往返链路；旧条目缺字段显示“来源/核验时间未知”，不批量伪造已核验状态 |
| `running-input.cjs` 已有输入版本、队列、重启中断处理及计划待核对；旧计划不能使空闲会话持续忙碌 | 另加“意图状态机”或把看板状态当作长期目标，会重复派发或重新出现旧任务压过新消息 | 复用 input_revision 与当前消息，不改派发/重试状态机。恢复文本须尊重用户后续纠正，原有仍适用的范围和禁止项继续保留，不把新消息自动解释为取消全部旧任务 |
| `cW / lW / iW / rW` 为恢复上下文构建有预算摘录；另有适配器原生会话恢复 | 为保留完整上一答而全量加载历史，会超预算；替换所有恢复流程可能影响服务商原生续聊 | 只修复生成恢复提示中的旧任务优先级和关键问答保留。优先保留最近问题、尾部选项与对应短回复，仍受总预算约束；不重写原生会话恢复 |
| `background-completion-policy.cjs` 区分 system_internal 通知与用户输入，按原始工具和轮次归属结果 | 新摘要/记忆提取若只按 role 或“最新一条”处理，可能把后台完成通知当作用户意图或新最终答复 | 保留来源、工具 ID 和轮次归属；新增提取和恢复摘录须检查合成通知与隐藏 context-reminder，不能把内部引导写成用户偏好或新请求 |

## 已确认的复现与边界

- 现有原生校验器将 50 字“部署状态类问题先读文档并实测，再作答”的长期原则判为 `mutable_world_state`；删掉其中“与部署状态”即可通过。说明按关键词拒绝存在误拦截，不能据此推断所有被拒内容都应保存。
- 对真实上一答复执行原生 320 token 前缀裁剪，1957 字剩 857 字，尾部“保持现状”选项丢失。复现证明摘录存在信息损失，不是当时真实模型请求的完整重放。
- 恢复提示确有“原始用户任务为权威、覆盖下方偏离内容”的措辞，须修正对后续有效更正的优先级。模型当时的精确完整输入未捕获，不把它描述成唯一已证实原因。
- 现有同主题合并和历史已经存在，但不等于具有可靠的事实时序冲突裁决；`updatedAt` / `capturedAt` 也不等于真实世界事实已重新核验。
- 现有模型评估会把部分模型不可用/异常转换成低可信“不值得记”；准确反馈必须检查评估层和工具返回层，不能只改界面文字。

## 收窄后的实施顺序与回归要求

1. **先修误拦截、准确反馈和恢复问答。** 同时覆盖显式保存与自动提取的准入，保持完成句更新路径。验证规则中出现部署/状态可正确判定、真正短期进度不冒充永久偏好、模型不可用及队列超时反馈准确；长答末尾选项加短回复、后续纠正、原范围禁止项与总 token 预算均保留。
2. **再补现有记忆的来源和时序。** 沿用类型、主题更新、项目范围和 change/索引同步；验证项目 A/B 隔离、同项目不同实体、旧摘要迟到、矛盾事实、手动确认/置顶/归档及新旧字段导入导出、重启、整合压缩往返。历史事实标记为最后已知，不能替代当前核验。
3. **最后优化自动提取。** 复用既有后台评估队列；不静默开启自动召回。验证谨慎模式候选审核、显式遗忘不被旧摘要重新激活、后台通知与内部提示不写成用户意图，并测消息发送耗时，确保不再新增前置等待。

实施时优先新增可读扩展和窄、可重复构建补丁；不改 immutable archive。需要修改源码时再运行 `npm run check` 及上述有意义的行为回归。本次仅新增审计文档，没有声称这些回归已通过。
